# Окно «Экономика и бюджет»: переделка UI (T-336, 2026-10-29)

Задача пользователя 2026-10-29: окно бюджета выглядит сумбурно. Хочется больше инфографики и
иконок, правильной группировки и деталей во всплывающем. Механика экономики **не меняется**: это
UI в `cp_ui` (+ короткий формат денег в `cp_tools` и одна чистая функция в `cp_economy`). Сейв
и сим не трогаются.

- **Было:** `.data/coord/shots/T-336-before-{overview,taxes,budgets,loans}.png`. Команда
  (release, из coord checkout, в обёртке `perl -e 'alarm 150; exec @ARGV'`):
  `cp_desktop --hidden --ui --scene town:5000 --open budget --budget-tab <tab> --lang ru --size 1600x1000 --speed 3 --screenshot <png>`.
- **Макет:** https://claude.ai/artifact/WWX3ZXPKB6L4No1n7kVapG — интерактивный: вкладки,
  период, ползунки пересчитывают суммы, кредиты берутся и гасятся, земля покупается; твик
  «debt» включает баннер долга. Цифры в макете выдуманы, цвета и шрифт — ориентир; в игре
  берём тему egui и `palette.rs`.
- **Связано:** T-335 (окно «Власть») вводит чипы и плитки. Если к началу T-336 они уже в
  master, переиспользуй их, а не пиши свои.

## 1. Что не так сейчас (по шотам)

1. **Сетка «Земля» на каждой вкладке.** `budget_window` после содержимого вкладки всегда зовёт
   `tiles::tile_section`, поэтому покупка участков висит под налогами, службами и кредитами.
2. **Деньги с копейками везде:** `$10 072 141,32`, `$24 592,32`. Длинные числа без пользы.
3. **Обзор:**
   - таблица на три колонки (день / эта неделя / прошлая) примерно в 20 строк, включая
     нулевые;
   - под ней блок «Прошлая неделя», который повторяет третью колонку;
   - блок «Доход по зонам» повторяет строки «Налог: …»;
   - два крошечных спарклайна без осей.
4. **Налоги:**
   - в каждой строке три числа под общим заголовком «последний день, эта неделя, прошлая
     неделя»;
   - ползунок не показывает последствий;
   - не видно «нейтральной» ставки, выше которой налог бьёт по довольству.
5. **Бюджеты служб:**
   - по две строки на службу: ползунок + «100%» + три кнопки 50/100/150 — четыре контрола на
     одно число;
   - красно-жёлто-зелёная полоса (баланс сектора, `services::bar`) без подписи;
   - «мощность ×1.00 · охват ×1.00» текстом;
   - цена в неделю есть только у части служб.
6. **Кредиты:**
   - карточки — строки текста;
   - закрытое предложение выглядит почти как открытое;
   - нет сводки долга и доли платежей в доходе.
7. **Шапка:**
   - «последний расчёт: неделя 2» — шум;
   - предупреждение о долге — строка «⚠» текстом.

## 2. Новая структура

### 2.1 Шапка окна (на любой вкладке)
Три плитки:
- **Казна** — короткая сумма и спарклайн за 7 дней (`CityStats::history[].balance`).
- **За день** — `daily_trend`, стрелка и цвет как сейчас в верхней панели.
- **Итог недели** — `last_week.balance()`; тултип: «Прошлая неделя закрыта: неделя N».

Точная сумма с копейками — в тултипе каждой плитки.

**Баннер долга** вместо строки «⚠»: по `debt_level`. Жёлтый — казна ниже нуля, красный — у
`NEAR_FLOOR_MARGIN` от `DEBT_FLOOR`. Текст из `debt_warning` плюс кнопка «Кредиты» (переключает
вкладку).

### 2.2 Вкладки с иконками
| Вкладка | Иконка |
|---|---|
| Обзор | `metrics` |
| Налоги | `district_tab_taxes` |
| Службы | `services` |
| Кредиты | `budget` |
| Земля | `overlay_land` |

- `BudgetTab` получает `Land`, `parse("land")`; `--budget-tab land` работает.
- Подпись `Budgets` → «Службы» (короче). Ключ `budgets` в `parse` остаётся, добавляется алиас
  `services`.
- Сетка земли уходит **только** во вкладку «Земля» (§2.7).

### 2.3 Обзор
1. **Переключатель периода** «Последний день / Эта неделя / Прошлая неделя» (сегменты) вместо
   трёх колонок. Выбор помнится в `BudgetDraft`, по умолчанию — «Прошлая неделя».
2. **Две полосы в одном масштабе:** «Доходы» и «Расходы» — горизонтальные стеки, куски по
   статьям, справа сумма. Масштаб общий (max из двух), поэтому видно, сколько остаётся.
   Тултип куска: имя и точная сумма.
3. **Два столбца строк:** доходы | расходы, отсортированы по убыванию.
   - Строка: иконка статьи, имя, короткая сумма. Фон строки — полоса пропорционально сумме
     (≈20% непрозрачности цвета статьи).
   - Нулевые строки скрыты (закрытые зоны уже скрыты, BUG-123).
   - Источник — `flow_rows` (не дублировать подсчёт).
   - Иконки — существующие: зоны — `zone_icon`; дороги — `roads`; трубы и ЛЭП — `power_line`;
     вода, канализация, электричество — `water` / `sewage` / `power`; автобусы и проезд —
     `transit`; туризм и отели — `tourism`; экспорт — `industry`; политики — иконка окна
     политик; кредиты — `budget`.
   - Статьи без иконки — сказать TL, новых не рисовать.
4. **График казны за 7 дней** (вместо двух спарклайнов) из `CityStats::history` (часовые
   сэмплы):
   - площадь под линией;
   - линия нуля;
   - пунктир `DEBT_FLOOR`, если он в масштабе;
   - вертикали по дням;
   - наведение — значение и день/час.
5. **Удаляются:** блок «Прошлая неделя» и «Доход по зонам» (дубли).

### 2.4 Налоги
- **Сверху:** «Налоги за неделю $X · N% дохода города» (доля от `last_week` всех доходов).
- **Строка на открытую зону:**
  - иконка, имя;
  - ползунок `TAX_MIN..=TAX_MAX`;
  - справа % и **оценка в неделю при этой ставке**: `≈ last_week.income_by_zone[i] × new / current`,
    со знаком «≈»; тултип «было $X при N%»;
  - мини-полоса **текущего** спроса зоны (`demand_fraction`, цвет по уровню). Налог в симе на
    спрос не влияет, поэтому полоса не «предсказывает», а просто стоит рядом для контекста.
- **На треке ползунка** засечка нейтральной ставки (`tax_neutral` из ручек довольства); выше неё
  трек оранжевый.
- **Тултип при перетаскивании** (§2.8, п. 2): «9% → 12%», оценка в неделю, для жилых зон —
  фактор довольства «налоги» до/после.
  - Формулу вынести в `cp_economy::contentment` как
    `pub fn tax_score(pct: u8, k: &ContentmentKnobs) -> u8` и звать её и в `contentment.rs`
    (строки 203–206), и в UI: одна формула, бит-в-бит то же, что сейчас.
  - Для коммерции, промышленности и офисов строки довольства нет: налог на них на довольство не
    влияет, так и написать.
- **Закрытые зоны** — строка чипов «Откроются позже: [иконка] Жилая (высокая) · 🔒 5 000» (порог
  из вехи, как в палитре зонирования).
- **Районный налог** (`districts.rs tax_block`) не трогаем.

### 2.5 Службы
- **Сверху:** стек-полоса расходов служб в неделю (`week_cost` по `budget_rows`), куски по
  службам, итог справа.
- **Группы с подзаголовком:**
  - Коммунальные — вода, канализация, электричество;
  - Городские службы — мусор, здоровье, похоронные, пожарные, полиция, образование, почта, …;
  - Транспорт — дороги, общественный транспорт;
  - Отдых — парки, если они в `BUDGETED`.

  Порядок внутри групп — `SERVICE_ORDER`. Скрытые закрытые службы остаются скрытыми.
- **Одна строка на службу:**
  - иконка (`kind_icon`), имя;
  - ползунок `BUDGET_MIN..=BUDGET_MAX` с засечкой на 100;
  - %: ниже 100 — оранжевый, выше — голубой;
  - **цена в неделю при этом значении** (`cost_at`). Где цены нет (0), чип не рисуется;
  - **шкала покрытия**: `supply / demand` сектора в процентах (черта = 100%), цвет: <90%
    красный, 90–105% жёлтый, выше — зелёный. Это та же величина, что сейчас за
    `services::bar`, но подписана.
    - Добавить `pub fn budget_coverage(view, kind) -> Option<f32>` рядом с `budget_balance`:
      минимум `supply / demand.max(1)` по секторам службы, без клампа.
    - Для дорог покрытия нет — «—».
- **Кнопки 50/100/150 удаляются.**
  - Двойной клик по ползунку → 100 (команда `budget_command(kind, 100)`).
  - Рядом с % маленькая ↺, видимая только когда значение ≠ 100.
  - Один `SetBudget` на отпускание — как сейчас (`Draft`).
- **В тултип имени** уходят:
  - `effect_text` словами: «мощность ×0,90 — участки гасят меньше»;
  - `transit_hint` для транспорта;
  - разница расхода против 100%;
  - для полиции — строка риска подкупа (`axis::police_terms`; после T-335 — откуда её
    отдаёт T-335).
- **Подсветка строки** (`draft.highlight`) остаётся.

### 2.6 Кредиты
- **Две плитки:**
  - «Долг банку» — сумма `principal_left + interest_left` активных;
  - «Платежи · N% дохода» — шкала, засечка на 30% (константа UI). Цвет: <15% зелёный,
    15–30% жёлтый, выше — красный. Под шкалой платёж в неделю.
- **Карточка предложения:**
  - крупно сумма;
  - чипы «ставка N%», «N нед», «−$X/нед» (оранжевый), «переплата $Y» (= платёж × недели −
    сумма);
  - кнопка «Взять».
  - Закрытое — приглушено, вместо кнопки «🔒 с N жит.».
  - Уже взятое — «взят».
- **Активный кредит:**
  - сумма, «осталось $X · N нед»;
  - полоса выплаченного (`1 − weeks_left / weeks`);
  - кнопка «Погасить $X» (`repay_loan_command`). Если денег не хватает — кнопка неактивна,
    тултип «не хватает $Z».
- Команды прежние: `TakeLoan` / `RepayLoan`.

### 2.7 Земля
- Сетка `TILES_PER_SIDE²` — та же `tiles::tile_section`, но только на этой вкладке. Плитки
  крупнее, три вида:
  - своя (синяя, «своя»);
  - можно купить (короткая цена);
  - недоступна (пунктир, без цены).
- Клик по покупаемой → карточка справа: участок, цена, ресурсы (если есть данные), кнопка
  «Купить за $X». Это тот же `pending`/`buy_tile` и тот же `BuyTile`; подтверждение — как
  сейчас (`land::confirm_window`) или прямо в карточке, решает dev, но одно, а не два.
- Кнопка «Показать на карте» включает оверлей `Land`.

### 2.8 Всплывающее
| Что | Как |
|---|---|
| Точная сумма (копейки) | тултип любой короткой суммы в окне |
| Деньги в верхней панели | короткий формат; тултип — точная сумма и три крупнейших статьи за день (`trend_breakdown`); клик открывает окно (как сейчас) |
| Перетаскивание налога | тултип у ползунка: ставка до → после, ≈ в неделю, фактор довольства (жилые) |
| Имя службы | эффект бюджета словами (§2.5) |
| Шкала покрытия | «даёт X — нужно Y — запас N%» двумя полосами |
| Кусок стек-полосы | имя статьи и точная сумма |
| Плитка «Итог недели» | номер закрытой недели (вместо «последний расчёт: неделя N» в шапке) |

## 3. Формат денег
`pub fn format_money_short(cost: Cost) -> String` в `cp_tools` рядом с `format_money`:
- |x| < 1 000 → `$740`;
- иначе `$24,6k`, `$1,2M` (одна цифра после запятой, разделитель по языку из `cp_locale`; если
  его там нет — запятая для ru, точка для en);
- знак минус — `−`.

Короткий формат — везде в этом окне и в верхней панели, точный — в тултипах. Тест на границы
(999, 1 000, 999 999, 1 000 000, отрицательные).

## 4. Иконки

`budget`, `overlay_land`, `zone_*`, `water`, `sewage`, `power`, `roads`, `power_line`,
`transit`, `tourism`, `industry`, `overlay_*` служб). Если для статьи расходов иконки нет —
сказать TL.

## 5. Тесты (UI, без плейтеста)
- Существующие тесты `budget.rs` (налоги закрытых зон, `budget_rows`, кредиты, `flow_rows`)
  остаются зелёными или переписываются на новые функции без потери проверок.
- Новые:
  - `format_money_short`: границы и знак;
  - `tax_score`: совпадает со старой формулой довольства на всём `TAX_MIN..=TAX_MAX`
    (headless, `cp_economy`);
  - `budget_coverage`: на фиксированном `SimView` даёт supply/demand, у дорог — `None`;
  - оценка налога: `≈ income × new / current`, при current = 0 — без деления на ноль;
  - вкладка «Земля»: сетка рисуется только на ней (на «Налогах» текста цены участка нет);
  - `--budget-tab land` открывает вкладку;
  - двойной клик по ползунку службы шлёт `SetBudget(kind, 100)`;
  - «Погасить» неактивна при нехватке денег.
- **Приёмка** (правило «visual bug acceptance»):
  - after-шоты той же командой, что before, по одному на вкладку:
    `.data/<slot>/shots/T-336-after-{overview,taxes,services,loans,land}.png`;
  - окно на каждой вкладке целиком помещается в 1600×1000;
  - нет копеек вне тултипов;
  - нет сетки земли вне вкладки «Земля»;
  - у каждой строки есть иконка.
