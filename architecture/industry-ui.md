2. **Вкладка ресурса — ряд из 6 одинаковых плиток с замками.**
   - Не видно, что из чего делается: поле даёт урожай, цех A — продукты, цех B — муку.
   - Не видно, сколько зданий уже стоит.

4. **«Торговля» в нижней панели обрезана по высоте:** видны 2 строки из 13. Сезон — мелкий

## 2. Новая структура

Одно окно `UiWindow::Industry` («Промышленность») с тремя вкладками: **Зоны · Цепочки ·
Рынок**.
- **Открывается:**
  - кнопкой «Окно» в нижней панели категории «Промышленность»;
  - иконкой `industry` в верхней панели (если там есть место для окон);
  - флагом `--open industry`, `--open industry:chains`, `--open industry:market`.
- **Заменяет** плавающее окно «Зоны» категории «Промышленность»: `areas_open` для `Industry`
  больше не рисует `area_list`. «Районы» и «Парки» оставить как есть.
- **Вкладка `Trade` уходит из нижней панели** промышленности, вместо неё «Рынок» в окне.
  Секция торговли в окне «Метрики» остаётся (она общая, `trade_table`).
- **Размер:** окно целиком помещается в 1600×1000 при 100% масштабе UI (≈ 780×880).

### 2.1 Шапка окна (на любой вкладке)

Четыре KPI-плитки:
- **Зоны:** число промзон и иконки их ресурсов.
- **Работники:** занято / мест во всех зданиях цепочек, тонкая шкала. Источник — §3.1.
- **Прибыль за неделю:** сумма `AreaEconomy::net()` всех промзон за прошлую неделю, ▲/▼ и цвет.
- **Грузовики в пути:** `freight.trucks`, плюс `↑ trucks_exporting` и `↓ trucks_importing`.

Тултип каждой плитки говорит, что посчитано и за какой период.

### 2.2 Вкладка «Зоны»

**Две колонки.**

Слева — **список зон** (≈ 236 px, скролл только у списка). Карточка зоны:
- квадрат в цвете ресурса (`swatch`) с иконкой ресурса;
- имя;
- «Ур. N»;
- прибыль прошлой недели (зелёная или оранжевая);
- кружок «!», если у зоны есть проблема. Тултип — первая проблема словами: «Поле S №2: склад
  полон», «Нет центра: зона не работает».

Клик выбирает зону (`tools.area.selected`), камеру не двигает. Внизу списка — «Новая зона»: 4
кнопки-иконки ресурсов. Клик делает то же, что сейчас пара «ресурс» + «Новая зона»: создать зону,
выбрать её, включить кисть.

Справа — **выбранная зона**.

1. **Шапка:**
   - квадрат ресурса 44 px;
   - поле имени: правка как сейчас, `RenameArea` на потере фокуса;
   - строка «Ресурс · N клеток · занято / мест работников»;
   - три иконки-кнопки: «Кисть» (`district_brush_s`, включает кисть на этой зоне), «Показать
     на карте» (`view`, камера к центру зоны), «Удалить» (`remove`, с подтверждением, как у
     сноса).
2. **Уровень:**
   - 5 делений, текущий уровень залит;
   - полоса опыта `xp / next_xp`;
   - строка «Ур. N+1 через ≈ D дн. откроет: [чипы]».
   - **Оценка дней:** `D = (next_xp − xp) / (опыт за прошлую неделю / 7)`. Опыт равен
     произведённым единицам (`cp_industry`, строка `a.xp += produced`), то есть сумме
     `AreaBook::produced` прошлой недели. Нет производства — «Ур. N+1: нужно ещё X опыта».
   - **Чипы — что откроется:** здания цепочки этой зоны и фабрики, у которых `min_level == N+1`
     (иконка и имя), плюс чип «склады +10%» (`industry_storage_per_level`). На уровне 5 — «Высший
     уровень».
3. **Подвкладки «Цепочка / Здания / Деньги»** (состояние в `UiState`, не в сейве).

**Пустая зона** (нет центра) вместо подвкладок показывает заглушку: иконка центра, «В зоне нет
центра», одна фраза и кнопка «Поставить центр». Кнопка выбирает инструмент постройки с
`Main`-зданием ресурса.

#### Цепочка

Три колонки слева направо: **Добыча → Переработка → Куда уходит**. Между колонками — ленты
потоков (painter-кривые). Толщина ленты пропорциональна недельному объёму, цвет — цвет груза
(`cargo.color` в контенте).

- **Карточка добычи или переработки** — одна на тип здания, а не на здание:
  - иконка, имя, «×count»;
  - выход в день: `output × count × средняя загрузка`;
  - у цеха — вход: «Урожай 60 → Мука 40 /дн» с цветными квадратиками грузов;
  - состояние: «✓ работает · 80%» (средняя загрузка = работники, §3.1), «▲ 2 работают, 1
    полно». Форма значка та же, что над зданием на карте (`cp_render::problem`).
  - Закрытые по уровню здания цепочки не показываются: они в чипах «откроет».
- **«Куда уходит» (за прошлую неделю):**
  - **Экспорт:** `AreaEconomy::exports` и строки по грузам с излишком. Излишек груза =
    произведено − съедено цехами зоны. Съеденное считается из `produced` выходов цехов по
    пропорции `inputs/outputs` их спеки: чистая функция `area_flows` (§3.2). Помечено «≈».
  - **Склад:** заполнение складов зоны (сумма запаса / сумма `storage_cap`), режим словами,
    полоса.
  - **Фабрики города:** сколько фабрик в городе берут грузы этой зоны (вход фабрики ∩ выходы
    зоны). Если таких нет, а фабрика по уровню доступна — фраза «Пищевая взяла бы продукты и
    муку» и кнопка «Поставить пищевую» (выбирает инструмент).
- **Под колонками:**
  - **«Запасы в зданиях зоны»:** одна полоса, сегменты по грузам в их цвете, «занято из
    места»;
  - **совет** (синяя плашка, максимум один): первое сработавшее правило из §3.3.

#### Здания

Строка на каждое здание цепочки в зоне, по ролям (центр, добыча, переработка, склад, фабрики):
- иконка;
- имя с номером («Поле S №2»);
- работники «5 / 6» и полоса;
- склад здания «220 / 220» и полоса в цвете главного груза;
- состояние значком и словом.

Клик по строке — камера к зданию и его инспектор. Сортировки нет, порядок стабильный по `BuildingId`.

#### Деньги

- **Переключатель «Прошлая неделя / Эта (идёт d из 7 дн.)»:** `AreaBooks::last` / `AreaBooks::now`.
  Для «этой» недели налоги и содержание ещё не начислены. Строки показываются как «—» с
  тултипом «начисляются в конце недели».
- **Водопад:** экспорт и налоги рабочих поднимают итог, импорт и содержание опускают, внизу
  синяя полоса «Чистая прибыль».
- Одна строка пояснения под графиком.

### 2.3 Вкладка «Цепочки»

Карта всех 13 грузов города: что город делает сам, что докупает, чего нет. Это главный
инструмент планирования, его в CS нет.

- **Четыре строки ресурсов:** [ресурс + «N зон · ур. max» или «нет зоны» / «нет центра»] → [сырьё]
  → [два продукта переработки].
- **Чип груза** показывает количество за прошлую неделю и состояние:
  - «делаем» — зелёная рамка: город производил груз;
  - «делаем и докупаем» — оранжевый пунктир: был и импорт этого груза; число «450 +80»;
  - «нет» — серый.
  Чип закрытого по уровню продукта показывает «ур. 2».
- **Источники:** производство — сумма `AreaBook::produced` всех зон; импорт и экспорт —
  `industry_ledger.last_by_cargo`.
- **Ниже — 4 карточки фабрик:**
  - иконка, имя;
  - состояние: «можно ставить» / «нужна зона ур. N» / «нужна промзона с центром»;
  - входы чипами с тем же состоянием грузов, «→ Товары 60/дн»;
  - строка пояснения: где ставить, какой вход придётся покупать.
- **Клики:**
  - по грузу — его карточка на «Рынке»;
  - по ресурсу — его зона на «Зонах» (или «Новая зона», если её нет);
  - по фабрике — инструмент постройки с ней.

### 2.4 Вкладка «Рынок»

Замена таблицы `trade_tray`. Данные — те же `trade_rows`.

- **Сверху:**
  - плитка сезона: глиф `season_icon` в кольце дней сезона, «Весна · ещё 7 дн.», строка
    `season_hint`;
  - две KPI: экспорт и импорт за неделю в деньгах (`IndustryLedger`).
- **«Грузы города»** (`in_city == true`) — сетка карточек в 2 колонки:
  - квадрат цвета и имя груза;
  - чип события «Дефицит · 3 дн.» / «Переизбыток · 5 дн.» (`TradeState`);
  - цена вывоза за единицу крупно и «▲ +50% к норме» (`export_change`);
  - спарклайн `history` за 30 дней с пунктиром нормы;
  - две полосы «вывоз / ввоз» за прошлую неделю: единицы и деньги.
  - Тултип карточки: что делает событие (множители из `MarketKnobs`: вывоз ×1,5 / ×0,5, ввоз
    ×2 / ×0,8, срыв половины заказов при дефиците).
- **«Город не делает и не покупает»** — строка компактных чипов: цвет, имя, цена, стрелка
  тренда.

### 2.5 Нижняя панель (категория «Промышленность»)

- **Вкладки:** Зоны · Сельское хоз. · Лесное хоз. · Руда · Нефть · **Фабрики**, справа кнопка
  «Окно». Вкладка «Торговля» убрана.
- **Вкладка ресурса** — цепочка слева направо колонками **Центр → Добыча → Переработка →
  Хранение → Дальше**, между колонками стрелки.
  - **Плитка:** иконка, имя, чип выходного груза («Урожай 40»), бейдж «×N», если в выбранной
    зоне уже стоит N таких.
  - **Закрытая плитка** — серая, бейдж «ур. 2» вместо замка-без-причины; причина остаётся в
    тултипе.
  - **«Дальше»** — ярлык фабрики, которая берёт продукты этой цепочки. Клик переключает на
    вкладку «Фабрики» и выбирает её.
- **Слева на вкладке ресурса — «Строим в зоне»:**
  - кнопка с цветом и именем выбранной зоны этого ресурса и «ур. N ▾» (выпадашка зон этого
    ресурса);
  - тонкая полоса опыта;
  - строка кистей.
  Бейджи «×N» и замки считаются по этой зоне. Реальное место постройки по-прежнему решает
  зона под курсором; выпадашка — только для подсказок.
- **Вкладка «Фабрики»:** 4 широкие плитки:
  - иконка, имя и цена;
  - входы чипами по состоянию грузов (как в §2.3);
  - строка состояния: «✓ можно: <зона> ур. N» / «нужна зона ур. N».
  - Блокировка — новая ветка `industry_lock` для `role == Factory`: лучшая по уровню промзона
    *любого* ресурса с центром.
- **Вкладка «Зоны»** панели: 4 ресурса и «Новая зона», как сейчас, плюс кнопка «Окно».

1. **Инспектор здания цепочки** (`industry_rows`, сейчас «Stock: X / Problem»):

2. **Склад** (`warehouse_controls`):

     тултипы — нынешние тексты;

   - строка `warehouse_hint`.
3. **Тосты:**
   - повышение уровня зоны: кружок с цифрой уровня, «<зона>: уровень 3», «Открыт <здание> ·

4. **Значки над зданиями** на карте уже есть (`cp_render::problem`, T-125/T-211). Не меняем. В

## 3. Данные и чистые функции

### 3.1 Работники зданий цепочек — новое поле `SimView`

Сим считает загрузку `f = filled / slots` внутри `run_industry`, но в `SimView` её нет. Добавить
`SimView.industry_jobs: Arc<BTreeMap<BuildingId, (u16 filled, u16 slots)>>`:
- только здания с `industry: Some(_)`;
- строится в `SimRunner::view()` из `CitizenGrid::jobs_filled` (сумма по 4 уровням образования)
  и `def.jobs`.

Это производное: не сейв, не чексумма, без новых зависимостей. Тест: в сцене с одним полем
и известным числом рабочих view отдаёт ту же пару, что `run_industry` берёт в `f`.

### 3.2 `cp_ui::industry` — чистые функции (тесты без окна)

- `area_buildings(view, area) -> Vec<ChainBuilding>`: здания цепочки зоны с ролью, номером в
  своём типе, работниками, запасом по грузам, `storage_cap` и проблемой. Порядок — роль, затем
  `BuildingId`.
- `area_flows(view, db, area) -> AreaFlows`:
  - произведено по грузу;
  - съедено цехами зоны (выходы цеха × `input/output` его спеки);
  - излишек;
  - загрузка по типу здания.
  Всё за прошлую неделю из `AreaBook::produced`.
- `area_unlocks(db, resource, level) -> Vec<BuildingDefId>`: что откроет уровень `level`.
- `level_eta_days(summary, last_produced) -> Option<u32>`.
- `cargo_status(view, db) -> [CargoStatus; 13]`: `Made { units, imported }` / `None`, для
  «Цепочек» и чипов фабрик.
- `factory_lock(view, db, def) -> Option<String>`: ветка `industry_lock` для фабрик.
- `area_tip(...) -> Option<String>` — правила совета, первое сработавшее:
  1. есть `NoMain` → «поставьте центр»;
  2. цех `NoInput` больше половины времени → «не хватает <сырья>: ещё одна <добыча>»;
  3. добыча `Full` → «склад полон: поставьте склад или переработку»;
  4. излишек сырья > 25% добычи и цех той же цепочки доступен → «<сырьё> уходит сырьём: цех или
     фабрика дадут больше»;
  5. загрузка < 60% → «мало работников: нужны жилые районы и дорога».

  Тексты — ключи локали.

### 3.3 Состояние UI

`UiState` получает:
- `industry_open`;
